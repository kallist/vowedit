## Actual local Agent host

Codex CLI 0.160.0, native executable, process-local stdio MCP configuration and official
mcp1.30.0 server. Actual host called capabilities/create/get_edit/propose/request_action/
get_run/get_report/get_activity. Host also listed/fetched scoped textual MCP resources.
Web attachment and decisions were separate automated Chromium fixture actions on the exact
returned draft URL; they were not Agent approval tools. No global host config was changed.
See [sanitized host evidence](evidence/agent-v03/actual-host.json) for IDs, transport and
observations. Raw host transcripts contain local paths, are ignored and are not published.

Actual initialize negotiation reported mcp_apps_html_advertised=false for the selected CLI.
It did not advertise the standard io.modelcontextprotocol/ui HTML extension; scoped resource
fetch succeeded as text, while HTML bridge/rendering was unavailable in that selected host. VowEdit advertises
web-fallback and returns textual authorized JSON resources. HOST EMBEDDED UI: NOT IMPLEMENTED,
NOT TESTED IN ACTUAL HOST. Conditional embedded acceptance is not claimed. Ordinary browser
screenshots and generic MCP documentation do not prove a native Codex sidebar. Official
references: [local MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli),
[MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview),
[UI resource/bridge](https://developers.openai.com/plugins/build/chatgpt-ui).
