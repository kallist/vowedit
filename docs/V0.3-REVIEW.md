# V0.3 self-review

## First implementation review

Reviewed current source and candidate diff against the merged V0.2 baseline, including
authentication, persistence, draft/action bindings, service/provider boundaries and browser
recovery. This review found and corrected these IMPORTANT issues:

- Candidate insertion/ranking changed a review list and falsely emitted user_reviewed.
  Compare existing candidate IDs and their reviews; generation now has a negative regression.
- Accepted actions were momentarily included in peer-staling activity; mark accepted state
  inside the same transaction before mutation, so it is only visible on commit. Approval
  activity precedes queue activity. Fault/replay and ordering regressions cover this boundary.
- Continuation could register a starter before the mutable child failed. Reuse one writer
  transaction for starter, child, required activity and decision. Fault/replay test verifies it.
- A shared client could encounter another client's actions and fail a draft read. Filter
  by principal on Agent reads; human Web sees the shared context's requests. Scope test added.
- Reusing an acknowledged revision after reload disabled decisions. Restore the presentation
  state for that revision; image acknowledgement is idempotent and preview failures disable
  acceptance. Rejection remains available without approving unseen pixels.
- Lost-save acknowledgement needed explicit exact-key retry, with local conflicts preserved.
  Browser regression covers committed-but-lost response and a second editor's local text.
- Adopt/continue needed the requested final candidate pixels visible on the card; added
  preview and independent pixel/manual-review states. Agent still supplies no confirmations.
- Browser session bootstrap needed concurrent protection; added a local lock and bounded
  sessions. Invalid bearer takes precedence over any browser cookie.

Preserved original assertions. Existing imported/boundary browser fixtures now bootstrap a
trusted browser session before their read-only provider counters. This retains the assertion
that import/preparation makes zero provider calls. Legacy anonymous API access intentionally
changes to authenticated local Web access. No provider/evaluator/ranking algorithms changed.

Known limits: same-OS-user shell is trusted; PNGs may be orphaned after a later DB rollback;
no distributed/multiworker support, cancellation, generic Agent tools, or automatic downgrade;
external unknown-charge interruption retains the existing fail-closed retry restrictions.
No real-provider generation was executed.
